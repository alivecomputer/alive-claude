# ALIVE v3.3 Codex Hooks and MCP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make ALIVE's Codex lifecycle integration and read-only MCP server work from the installed plugin cache.

**Architecture:** Native plugin hooks use current Codex events, regex matchers, `PLUGIN_ROOT`, and `PLUGIN_DATA`. A packaged read-only MCP process discovers the world from explicit environment/roots and exposes bounded context without write tools.

**Tech Stack:** Bash, Python, JSON hook protocol, MCP stdio, pytest for recovered MCP tests.

## Global Constraints

- Hooks are advisory and must not be described as an enforcement boundary.
- Hook commands must tolerate no world, malformed input, and disabled/untrusted hooks.
- MCP performs no network calls and exposes no mutations.
