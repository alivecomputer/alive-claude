# ALIVE v3.3 Codex Private Alpha Design

## Decision

ALIVE v3.3 remains the filesystem-first v3 product. The existing walnut format
and `plugins/alive` implementation stay canonical. `codex/` becomes a complete,
deterministically built Codex adapter containing skills, native lifecycle hooks,
shared projection scripts, templates, rules, and a read-only MCP server.

The private alpha is accepted only when the installed cache artifact—not the
development checkout—passes package, hook, MCP, install, upgrade, uninstall,
and cross-session walnut recovery tests.

## Boundaries

- Existing walnuts remain readable and writable without migration.
- New schema fields are optional and ignored safely by older v3 runtimes.
- The local world is authoritative. Hosted surfaces receive explicit exports.
- MCP is read-only. Writes occur through explicit ALIVE skills and scripts.
- Hook-assisted persistence is best-effort. Explicit save is the guaranteed path.
- No code, schema, service, or account model from `exitplatforms` is required.
- Uninstall never deletes a world or user-authored walnut data.

## Package Architecture

`codex/` is a self-contained plugin source and release input. Runtime-neutral
files copied from `plugins/alive` are generated by an allowlisted sync script;
Codex-specific files are maintained in `codex/`. A validation test fails when
the generated copies diverge from their canonical sources.

The plugin manifest explicitly declares:

- `skills: ./skills/`
- `hooks: ./hooks/hooks.json`
- `mcpServers: ./.mcp.json`

Hook commands use `PLUGIN_ROOT` and writable state uses `PLUGIN_DATA`. They do
not edit user-level `hooks.json` or depend on `CODEX_PLUGIN_ROOT`.

The MCP server exposes read-only world discovery, walnut orientation, search,
tasks, bundles, and kernel resources. It performs no network calls and rejects
write-shaped requests. Its launcher resolves only packaged paths.

## Lifecycle Contract

| Capability | Private-alpha contract |
|---|---|
| Explicit load | Guaranteed through the load skill and packaged scripts |
| Explicit save | Guaranteed through the save skill and synchronous projection |
| Session startup orientation | Tested when plugin hooks are trusted and enabled |
| Resume/clear/compact recovery | Tested best-effort through supported events |
| Tool guards | Advisory only; hooks are concurrent and are not a security boundary |
| Hosted tool observation | Unsupported where Codex does not emit local hook events |
| Forced final save on every exit | Unsupported; abrupt termination can bypass hooks |
| Cross-session recovery | Guaranteed after a completed explicit save |

## Distribution

The source repository exposes a private Codex marketplace whose local plugin
source is `codex/`. `install.sh` uses Codex's native `plugin marketplace add`
and `plugin add` commands. It does not merge global hooks or append feature
flags. `upgrade.sh`, `uninstall.sh`, and `doctor.sh` are idempotent and preserve
unrelated config and worlds.

The tested Codex version and platform are recorded in generated evidence. A
version outside the tested range produces a warning, not an invented guarantee.

## End-to-End Proof

The proof uses a copy of a real walnut inside a temporary world and a fresh
`CODEX_HOME`. It installs the marketplace artifact, starts one real Codex
process to load and explicitly save a unique decision/task, exits, then starts a
distinct Codex process with no conversational context and verifies recovery
from walnut files. File hashes prove the live source walnut was untouched.

If credentials or network policy prevent a real model-backed session, the E2E
suite reports `BLOCKED`, while deterministic process-level tests still run. A
blocked model test is never reported as passed.

## v3.3 Product Projections

Private previews, `user.walnut.world`, and marketplace listings are projections,
not alternate sources of truth. Each export has an explicit include set,
sensitivity check, digest, provenance, expiry or rollback mechanism, and public
visibility state. Wildcard routing alone does not make a preview private.

Task evolution is additive: stable IDs plus optional `kind`, `direction`,
`counterparty`, `source_ref`, `updated`, `review_at`, `blocked_by`, `done_when`,
and `recurrence`. Context pruning archives material while retaining retrieval,
with byte/token budgets, log chapters, working-state expiry, and a doctor report.

These product projections are a separately gated v3.3 roadmap. They are not
part of the Codex private-alpha acceptance test unless a later decision promotes
them into scope.

## Assumptions Under Test

1. `plugins/alive` can remain canonical without requiring Codex runtime forks.
2. The current walnut format tolerates additive fields and derived projections.
3. Codex plugin cache copies preserve executable scripts and packaged MCP files.
4. Native hook environment variables and matchers behave as documented.
5. Read-only MCP is useful enough for private alpha without mutation tools.
6. A local/repository marketplace is an adequate private distribution channel.
7. Explicit save plus a fresh-process recovery test is the honest persistence bar.
