# ALIVE Codex 3.3.0-alpha.2

This is a release-candidate hotfix for the private beta cohort.

## Fixed

- Removed the unsupported top-level `hooks` manifest field. Codex discovers
  the packaged definitions from `hooks/hooks.json`.
- Added the required `interface.capabilities` metadata.
- Added current `exec_command`, namespaced exec, and namespaced
  `apply_patch` hook matcher aliases while retaining compatibility aliases.
- Made session startup idempotent. A repeated startup event now resumes the
  existing squirrel record rather than erasing its walnut, save count, and
  recovery state.
- The installer now prefers a working bundled macOS Codex binary and rejects a
  broken launcher with a precise diagnostic.
- Install and upgrade now refuse a profile with another enabled ALIVE product.
- Doctor now checks the current manifest contract, current hook aliases, MCP
  imports, and ALIVE product conflicts.

## Verified

- Current Codex plugin validator: pass.
- Package, hook, installer, MCP wiring, marketplace, and two-process walnut
  tests: 32/32 pass.
- Fresh install and doctor using `codex-cli 0.146.0-alpha.3.1`: pass.
- Installed MCP initialize plus `tools/list`: pass, 12 read-only tools.
- Minimal isolated copy of a real walnut: loaded, changed, saved, projected,
  and recovered by a distinct second process; original kernel hashes unchanged.

## Honest boundary

Lifecycle hooks remain best-effort, trust-gated assistance. Explicit
`alive-save` is the supported persistence guarantee. A model-backed remote
private-walnut rerun for this exact hotfix is not claimed until its
minimum-disclosure payload receives separate provider approval.
